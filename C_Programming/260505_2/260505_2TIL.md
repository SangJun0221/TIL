# 260505_2 C언어 트러블슈팅: max/min 반복문에서 첫 정상 입력값으로 기준값 초기화하기

## 1. 문제 요약
정수를 반복해서 입력받아, 입력값 중 `최댓값`과 `최솟값`을 출력하는 프로그램 구현.

**[처리 조건]**
* 정수를 계속 입력받는다.
* 입력값이 `-1`이면 입력을 종료한다.
* `-1`은 계산에 포함하지 않는다.
* 첫 번째 정상 입력값으로 `max`, `min`을 초기화한다.
* 이후 입력값과 비교하여 `max`, `min`을 갱신한다.
* 반복이 종료되면 최댓값과 최솟값을 출력한다.

**[입력 예시]**
```text
4
9
2
7
-1
````

**[출력 예시]**

```text
MAX = 9
MIN = 2
```

---

## 2. 초기 구현

```c
#define _CRT_SECURE_NO_WARNINGS
#include <stdio.h>

int main()
{
	int a;
	int max = 0;
	int min = 0;
	int frist = 1;

	for (;;)
	{
		scanf("%d", &a);

		if (a == -1)
		{
			break;
		}

		if (frist)
		{
			max = a;
			min = a;
			frist = 0;
		}
		else
		{
			if (a > max)
			{
				max = a;
			}
			if (a < min)
			{
				min = a;
			}
		}
	}

	printf("max = %d\n", max);
	printf("min = %d", min);

	return 0;
}
```

## 3. 문제 상황

코드의 전체 흐름은 맞았지만, `max/min` 문제에서 왜 `first` 변수가 필요한지 이해가 불분명했다.

초기 코드에서는 `max = 0`, `min = 0`으로 시작했지만, 실제로는 이 값들이 비교 기준으로 쓰이면 위험할 수 있다.

예를 들어 입력값이 모두 양수이면 큰 문제가 없어 보일 수 있다.
하지만 일반적인 `max/min` 문제에서는 입력값의 범위를 항상 확신할 수 없으므로, 임의의 값 `0`을 기준값으로 두는 방식은 안전하지 않다.

또한 변수명 `frist`는 오타였고, 출력 형식도 문제 예시의 `MAX`, `MIN`과 달랐다.

---

## 4. 원인 분석

이번 문제의 핵심은 **최댓값과 최솟값을 비교하려면 먼저 기준값이 필요하다**는 점이다.

`sum`이나 `count` 문제는 처음값을 `0`으로 두는 것이 자연스럽다.

```c
int sum = 0;
int count = 0;
```

하지만 `max/min` 문제에서는 `0`이 항상 안전한 기준값이 아니다.

예를 들어 `min = 0`으로 시작하면, 실제 입력값이 `5, 3, 2`일 때 최솟값은 `2`인데도 `min`이 `0`으로 남을 수 있다.

따라서 `max`, `min`은 첫 번째 정상 입력값으로 초기화해야 한다.

```c
if (first)
{
	max = a;
	min = a;
	first = 0;
}
```

이 구조는 첫 번째 입력값을 비교 기준으로 만들고, 이후 입력값부터 실제 비교 갱신을 수행하게 해준다.

즉, `first` 변수는 **첫 번째 정상 입력값인지 구분하기 위한 플래그**다.

## 5. 수정 과정

초기 코드에서 다음 부분을 수정했다.

* `frist` 오타를 `first`로 수정
* `max = 0`, `min = 0` 초기화를 제거
* 첫 번째 정상 입력값으로 `max`, `min`을 초기화하는 구조를 유지
* 출력 형식을 문제 예시에 맞게 `MAX`, `MIN`으로 수정

**[수정 전]**

```c
int a;
int max = 0;
int min = 0;
int frist = 1;
```

**[수정 후]**

```c
int a;
int max;
int min;
int first = 1;
```

또한 첫 번째 정상 입력값이 들어왔을 때 아래 코드로 기준값을 설정했다.

```c
if (first)
{
	max = a;
	min = a;
	first = 0;
}
```

이후부터는 현재 입력값과 기존 `max`, `min`을 비교하여 갱신한다.

```c
if (a > max)
{
	max = a;
}

if (a < min)
{
	min = a;
}
```

## 7. 핵심 인사이트 (Takeaway) & Action Item

`max/min` 문제는 `sum/count` 문제와 초기화 방식이 다르다.

`sum`과 `count`는 `0`에서 시작하는 것이 자연스럽지만, `max`와 `min`은 임의의 값으로 시작하면 잘못된 결과가 나올 수 있다.

따라서 `max/min` 문제에서는 첫 번째 정상 입력값을 기준값으로 삼아야 한다.

이번 문제의 핵심 구조는 다음과 같다.

```text
입력 받기 -> 종료값 검사 -> 첫 입력이면 max/min 초기화 -> 이후 입력이면 비교 갱신
```

특히 `first`는 단순한 보조 변수가 아니라, **첫 입력 처리와 이후 비교 처리를 분리하기 위한 플래그**다.

* [ ] 첫 번째 정상 입력값으로 `max`, `min`을 초기화하기
* [ ] `first` 플래그로 첫 입력 처리와 이후 비교 갱신을 분리하기
* [ ] 반복 입력 문제에서는 `-1` 같은 sentinel 값을 입력 직후 먼저 검사하기
